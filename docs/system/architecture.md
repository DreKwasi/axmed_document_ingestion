## Current state

The project is a single-repository FastAPI + Vue 3 document-intelligence system. The source PRD is [axmed_document_intelligence_prd.md](../product/axmed_document_intelligence_prd.md); the execution order is in [implementation-plan.md](../plans/implementation-plan.md). The backend map is [backend/app/README.md](../../backend/app/README.md): `api/` composes HTTP, `application/` contains use cases, `domain/` contains canonical interpretation and LangChain extraction (`app.domain.langchain_extractor`), `infrastructure/` contains persistence, `workers/` contains Huey execution, `security/` contains redaction, and `core/` contains configuration. Checked-in Alembic migrations persist batches, documents, quotations, source files under a generated local name, LiteParse representations, field evidence, fingerprinted mappings, review commands, correction evidence, review-learning jobs, email semantic-extraction jobs, processing events, model invocations, and evaluation runs in `data/app.db`; Huey state lives separately in `data/tasks.db`. Multi-file batch upload creates a `batches` record and derives aggregate progress directly from independent child document jobs; unparseable files fail safely with an isolated failure reason without disrupting sibling documents. The architecture has two explicit intake paths: structured JSON uses deterministic schema recognition and trusted mapping memory; unstructured PDF, EML, and image inputs use format-specific parsing (LiteParse, MIME, and PaddleOCR) to retain source representation before PII-safe semantic extraction. All paths converge on `CanonicalQuotation`, then deterministic commercial validation/derivation, confidence, provenance, and human review. Processing events are the browser/worker boundary and are replayed through reconnectable SSE. GitHub Actions CI and automated PII audit checks enforce delivery hardening.

The PDF boundary deliberately retains LiteParse's raw page JSON and parsed page representation; the application does not build a universal table-reconstruction or Markdown conversion layer. LiteParse output is evidence for the semantic extractor, not a canonical quotation.

Quotation snapshots remain in `quotations.payload_json` for immutable revision compatibility. The active line-item projection is normalized across `quotation_line_items` and child tables for INNs, strengths, price tiers, adjustments, and registered markets. Every non-null extracted leaf is also persisted in `quotation_field_values` with its value, confidence, extraction provenance, and human-review status; the API exposes these as `field_reviews`. Alembic migrations `20260906_12` through `20260906_14` backfill and maintain these projections.
