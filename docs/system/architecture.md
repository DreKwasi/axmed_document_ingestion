## Current state

The project is a single-repository FastAPI + Vue 3 document-intelligence system. The source PRD is [axmed_document_intelligence_prd.md](../product/axmed_document_intelligence_prd.md); the execution order is in [implementation-plan.md](../plans/implementation-plan.md). The backend map is [backend/app/README.md](../../backend/app/README.md): `api.py` owns FastAPI setup and every public route; `documents.py` owns document and review operations; `extraction/` groups parsers, extraction pipelines, confidence, contracts, and normalization; `models.py` and `database.py` make persistence explicit; `events.py` owns processing activity; and `security/` owns redaction. There is no worker package or separate queue runtime. One `POST /api/v1/documents` request accepts one or many files, returns one array of document records, and isolates failures when several files are uploaded together. It does not create a separate batch record.

Confidence is exposed through two independent API summaries. `extraction_confidence` is a weighted source-recovery score built from source format, machine readability, parser quality, grounded evidence, and OCR quality. `mapping_confidence` is a canonical-field assignment score built from direct source paths, row/cell association, provenance, reconciliation, and conflicts. `mapping_issues` is a deduplicated actionable list with an affected product-detail section; it replaces the synthetic review-issue count. The UI does not calculate or display a lowest-field confidence band.

Checked-in Alembic migrations persist documents, quotations, source files under generated local names, LiteParse representations, canonical field evidence, extracted source facts, review commands, processing events, model invocations, and developer evaluation runs in `backend/data/app.db`. JSON uploads use a recursive, in-memory structural profile and a per-document semantic extractor. The extractor returns source facts with raw values and JSONPaths; direct claims are value-checked against their pointers, then only certainly interpretable facts populate `CanonicalQuotation`. Unmapped facts are persisted, do not lower extraction confidence or create review issues, and are deliberately absent from the current product drawer. JSON profiles, fingerprints, mapping reuse, mapping confirmation, and correction learning are not stored. Unstructured PDF, EML, and image inputs use format-specific parsing (LiteParse, MIME, and PaddleOCR) before semantic extraction. OCR confidence and geometry remain in the redacted provider record for audit, while Gemini receives readable redacted OCR page text plus the original source media; no deterministic OCR row mapping sits between them. Sending original media is an explicit provider privacy boundary because pixel content cannot be text-redacted. All paths converge on deterministic commercial validation/derivation, field confidence, provenance, and human review. For unstructured documents the LLM receives parsed source context and is responsible for interpreting supplier quotation references, buyer RFQ references, supplier address country, named Incoterm place/country, and explicit product-origin statements; supplier-shaped regular expressions are not part of this semantic step. An Incoterm location is persisted as commercial context and never treated as evidence of product origin. Transit, shipping, or delivery duration is not assigned to product lead time unless the source explicitly identifies it as lead time. Full dosage-form phrases are retained and route is not modeled separately. Field confidence is an evidence-based `High`, `Medium`, or `Low` decision from source clarity, association certainty, independent validation, and conflicts; it is never an average or schema-completeness score. An extraction with at least one product becomes `pending_review`; a zero-product result becomes `failed`, with validated source facts retained as not reviewable. Only a human can move a reviewable source to `approved` or `rejected`, and a correction is an auditable event that leaves it pending until that decision. Processing events are replayed through reconnectable SSE. The Home source workspace consumes a source-level summary while the detail view reads normalized product data and canonical field evidence. GitHub Actions CI and automated PII audit checks enforce delivery hardening.

For image sources, OCR is both a continuous source-quality signal and a hard safety gate. The default gate accepts lines at or above 0.80 confidence and requires at least 60% of detected lines to clear that floor; both values are configurable. A source below the gate fails without invoking semantic extraction. Above the gate, OCR-assisted extraction receives only accepted text lines and direct vision receives a masked PNG containing only accepted OCR regions. The two approaches remain peer attempts and neither can become canonical automatically. Home projects them as two source results. Mapping is assessed per result, while both share a source-condition extraction score.

The PDF boundary deliberately retains LiteParse's raw page JSON and parsed page representation; the application does not build a universal table-reconstruction or Markdown conversion layer. LiteParse output is evidence for the semantic extractor, not a canonical quotation. The primary semantic call receives the layout-aware representation for table fidelity. A second, compact text-only LLM enrichment call receives the PDF reading order and the existing source keys, then fills only missing `Supply` and `Regulatory` fields. It cannot overwrite table-derived product, quantity, price, packaging, or commercial facts. Passing text from every page preserves scoped footnotes on table pages while avoiding the repeated layout geometry; it reliably applies semantic note scope (single item, list/range, exception, or remainder) to each line item.

Quotation snapshots remain in `quotations.payload_json` for immutable revision compatibility. The active line-item projection is normalized across `quotation_line_items` and child tables for INNs, strengths, price tiers, adjustments, and registered markets. Shipment HS customs codes remain document-level commercial terms; ATC codes and a separate product route are not modeled. Every normalized canonical leaf is persisted in `quotation_field_values` with its value, source provenance, confidence category/reason, and human-review status; the API exposes these as `field_reviews`. `field_evidence` stores actual semantic source locations/excerpts and human corrections only for canonical fields. `extracted_source_facts` stores all JSON facts, including unmapped ones, with their JSONPath and source-recovery confidence. Derived normalized prices persist their formula, origin flag, and deterministic validation status, and expose no extraction-confidence band. They are hidden from the overview table and rounded for display to no more decimal places than the quoted price. Deleting a source removes its exact stored upload and all document-scoped extraction, review, event, evidence, source-fact, and normalized projection records. `has_corrections` identifies an eventual approval with audited changes. `reviews.rejection_reason` retains the required structured reason. Alembic migration `20260907_19` replaces retired JSON mapping state with source-fact persistence; `20260907_20` removes redundant batch persistence; `20260907_21` marks existing unreviewed zero-product quotations as failed without changing completed human decisions.

Background-task progress is persisted before each meaningful semantic boundary and exposed through `GET /api/v1/documents/{id}/events` and the matching SSE stream. PDF and email extraction report preparation, semantic identification, normalization, completion, waiting, and failure; event serialization adds a user-safe `phase`, `message`, and redacted metadata. The Vue detail view replays these events as an extraction activity timeline, so reconnects do not lose the explanation of what the API is doing. OCR/provider internals remain backend state and are not presented as a user-facing source status.

The API terminal log is an operator-facing complement to those persisted events. It records safe lifecycle boundaries—task scheduled, started, completed with duration, or failed with exception class—using short record IDs only. Model source text, credentials, and raw provider responses are never logged.
