## Current state

The project is a single-repository FastAPI + Vue 3 document-intelligence system. The source PRD is [axmed_document_intelligence_prd.md](../product/axmed_document_intelligence_prd.md); the execution order is in [implementation-plan.md](../plans/implementation-plan.md). The backend map is [backend/app/README.md](../../backend/app/README.md): `api/` composes HTTP, `application/` contains use cases, `domain/` contains canonical interpretation and LangChain extraction (`app.domain.langchain_extractor`), `infrastructure/` contains persistence, `workers/` contains Huey execution, `security/` contains redaction, and `core/` contains configuration. Checked-in Alembic migrations persist batches, documents, quotations, source files under a generated local name, LiteParse representations, field evidence, fingerprinted mappings, review commands, correction evidence, review-learning jobs, email semantic-extraction jobs, processing events, model invocations, and evaluation runs in `backend/data/app.db`; Huey state lives separately in `backend/data/tasks.db`. Relative operational paths resolve from `backend/`, so API and Huey processes share the same database, queue, and source-upload directory regardless of their working directory. Multi-file batch upload creates a `batches` record and derives aggregate progress directly from independent child document jobs; unparseable files fail safely with an isolated failure reason without disrupting sibling documents. The architecture has two explicit intake paths: structured JSON uses deterministic schema recognition and trusted mapping memory; unstructured PDF, EML, and image inputs use format-specific parsing (LiteParse, MIME, and PaddleOCR) to retain source representation before PII-safe semantic extraction. All paths converge on `CanonicalQuotation`, then deterministic commercial validation/derivation, field confidence, provenance, and human review. Field confidence is an evidence-based `High`, `Medium`, or `Low` decision from source clarity, association certainty, independent validation, and conflicts; it is never an average or schema-completeness score. Missing values are commercial-availability exceptions, while derived values carry formula and validation status rather than extraction confidence. The system stores its independent routing decision (`auto_accepted` or `needs_review`) separately from the later human outcome (`unreviewed`, `approved`, `corrected`, or `rejected`). Processing events are the browser/worker boundary and are replayed through reconnectable SSE. The Home source workspace consumes a source-level summary (availability, system decision, product counts, issues, and notes) while the detail view reads normalized product data and field-level review evidence. GitHub Actions CI and automated PII audit checks enforce delivery hardening.

The PDF boundary deliberately retains LiteParse's raw page JSON and parsed page representation; the application does not build a universal table-reconstruction or Markdown conversion layer. LiteParse output is evidence for the semantic extractor, not a canonical quotation.

Quotation snapshots remain in `quotations.payload_json` for immutable revision compatibility. The active line-item projection is normalized across `quotation_line_items` and child tables for INNs, strengths, price tiers, adjustments, and registered markets. Every non-null extracted leaf is also persisted in `quotation_field_values` with its value, raw evidence provenance, confidence category/reason, and human-review status; the API exposes these as `field_reviews`. Derived normalized prices persist their formula, origin flag, and deterministic validation status, and expose no extraction-confidence band. `quotations.system_decision` supports the exception-only `GET /api/v1/review-queue`, while all sources remain available from `GET /api/v1/documents`. `reviews.rejection_reason` retains the required structured reason. Alembic migrations `20260906_12` through `20260907_16` backfill and maintain these projections.

Worker progress is persisted before each meaningful semantic boundary and exposed through `GET /api/v1/documents/{id}/events` and the matching SSE stream. PDF and email extraction report preparation, semantic identification, normalization, completion, waiting, and failure; event serialization adds a user-safe `phase`, `message`, and redacted metadata. The Vue detail view replays these events as an extraction activity timeline, so reconnects do not lose the explanation of what the worker is doing. OCR/provider internals remain backend state and are not presented as a user-facing source status.
